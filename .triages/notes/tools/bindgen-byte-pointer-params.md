---
name: bindgen-byte-pointer-params
description: "tools/main.py binds void*/char-sized pointer params as CRefBytePtr/CMutBytePtr by constness; returns and fields stay CVoidPtr"
updated: 2026-11-06
---

`_pointer_to` maps a parameter whose pointee is `void` or any char-sized type (plain, `signed`, `unsigned char`,
`uint8_t`; `BYTE_KINDS`) to `CRefBytePtr` when the pointee is `const`, else `CMutBytePtr`. `void*` is treated the same
as `char*`, buffer or handle alike. Returns, struct fields and `T**` pointees stay `CVoidPtr`; pointers to incomplete
structs (`BIO*`, `SSL*`) stay `CVoidPtr` handles. Before 2026-11-06 `void*` was `CVoidPtr`, `char*` was `CCharPtr`
whatever its constness, and `unsigned char*` fell through to `&mut CUChar` (a one-byte borrow).

**Why:** outside projects can only build these two types (through `std::cffi::view_ptr_ref` / `view_ptr_mut`); they
cannot dereference them, and constness decides whether c may write. Keeping `void*` as a handle would not have fixed
the returned-pointer round trip (`strdup` → `free` breaks for `char*` too), so both are symmetric and the round trip
needs a null-checked `CVoidPtr` → byte pointer conversion in std.

**How to apply:** a closure's parameters also go through `Pos.PARAM`, so a callback receiving `char*` would get an
unreadable `CMutBytePtr`; give callback params their own position before binding one (sppc's closures take none).
`realloc(NULL, n)` can no longer be expressed, as the byte pointers are `NonNull`. Std's stub is regenerated by
`post_merge.yaml`, so std's `std::cffi` must declare both types first (SPP-STL `ffi-byte-pointers-via-cffi`).
